# 인수 확인표와 주의사항

아래 항목은 완료 표시가 아니라 인수자가 수행할 확인표이다. 담당자·검증일·기기/OS·기준 커밋·결과를 별도 기록한다.

## 반드시 확인할 보안 한계

- 현재 서버는 다수 요청에서 `X-User-Id`로 사용자를 식별한다. 화면의 로그인/권한 분리가 서명된 서버 세션 기반 인증과 같은 수준은 아니다. ID 위조 등 위협을 검토하고 서버 세션/토큰·만료·권한 검증을 우선 개선한다.
- 암호 저장에 단순 SHA-256 비교가 사용된다. 기본 암호 대체값과 배송 계정 무비밀번호 진입도 존재한다. 일반 고객용 공개 서비스 수준의 인증으로 간주하지 않는다. 기존 계정 이관을 고려해 salted password KDF와 강제 초기 암호 변경을 설계한다.
- DB 계정·공개키·터널·관리자 권한을 따로 점검한다. CORS 설정만으로 인증/접근 통제가 해결되지 않는다. DB/SSH를 인터넷 전체에 개방하지 않는다.
- 사진·주소·전화번호·직원 실시간 위치는 개인정보이다. 접근 권한, 공유 링크 유출, 보존/삭제 정책, 배송 위치 수집 동의와 접근 기록을 검토한다.
- API 키를 과거 대화/파일로 전달한 적이 있다면 재발급 필요성을 검토한다. 공개 JS SDK 키와 서버 REST 비밀키를 구분한다. 인계 자료에 실제 키를 복사하지 않는다.
- 종속성 보안 업데이트, Play 정책 적합성, 운영 DB 복원, 화면 꺼짐 위치 추적은 이 문서 작성만으로 검증된 것이 아니다.

## 기능 인수 확인표

- [ ] 관리자/직원 로그인, 잘못된 암호, 비밀번호 변경, 비활성 멤버 접근을 확인했다.
- [ ] 배송 계정은 배송 UI만 보이며 다른 API 접근 권한도 별도로 검증했다.
- [ ] A/B/날짜 품번 파싱, 입력한 접수 날짜와 표시 날짜, 중복 접수를 확인했다.
- [ ] 진행 목록의 사진 없는 항목에서도 `+`로 올리고 메인 화면이 유지된다.
- [ ] 연속 촬영 → 미리보기 선택/삭제 → 업로드가 동작한다.
- [ ] Android 갤러리 다중 선택과 Fold 분할 화면 이미지 드롭이 동작한다.
- [ ] 업로드 중 통신 끊김/서버 중단 후 남은 전송을 복구하고 건수와 파일을 확인했다.
- [ ] 사진 고정 개수와 무관하게 1/2/3열이 유지되고 고정 사진을 좌우로 넘길 수 있다.
- [ ] 완료 목록 공유는 저장한 템플릿을 사용하고 화면을 유지하며 취소 시 상태를 오인 변경하지 않는다.
- [ ] 배송전/링크전송/배송완료, 픽업전/링크전송의 실제 상태 변경을 확인했다.
- [ ] 고객 링크에서 지정한 전/탈거/후 사진만 보이고 토큰 링크를 그대로 유지한다.
- [ ] 카페 테스트 게시판에서 제목·본문·사진·플레이스와 게시 성공 URL을 확인했다. 오류 뒤 중복 게시되지 않는다.
- [ ] Kakao 지도, 동+아파트 검색, 광주 기본 검색, 도로 경로와 사무실 복귀가 맞다.
- [ ] 주소 검색 실패 시 누락을 숨기지 않으며 순서 드래그와 주소만 복사가 동작한다.
- [ ] 관리자가 배송자 위치를 볼 수 있다. Android 화면 꺼짐/다른 앱 사용 중 갱신도 실기기로 확인했다.
- [ ] 지도와 알림의 이전/다음/종료, 위치 권한 거절, 알림 거절, 로그아웃 후 추적 종료를 확인했다.
- [ ] 앱 뒤로가기, 종료 확인, 재실행과 스토어 업데이트 안내를 확인했다.
- [ ] 직원 근태/정산, 채팅 만료, 사진 휴지통 복원/만료 동작을 확인했다.
- [ ] 별도 환경에 DB+사진을 복원했고, 운영 PC 재부팅 후 시작 절차를 확인했다.

## 장애 대응 첫 확인

| 증상 | 우선 확인 |
| --- | --- |
| 웹/앱 모두 연결 안 됨 | MariaDB → 로컬 `/api/health` → 관리 프로세스 → Cloudflare Tunnel/DNS 순서로 확인 |
| 포트 3000 사용 중 | `Get-NetTCPConnection -LocalPort 3000`의 소유 프로세스 확인. 다른 프로그램을 무작정 종료하지 않음 |
| DB `auth_gssapi_client` 오류 | 실제 접속 계정과 인증 플러그인, 배치의 MYSQL_USER 덮어쓰기를 확인. 전용 DB 계정을 올바르게 구성 |
| 지도 인증 실패 / 빈 지도 | Kakao 앱 API 활성화, JS 키, 지도 페이지 도메인, iframe 출처, 네트워크 오류 확인 |
| 주소/동선 실패 | Local/Mobility 권한과 REST 키·쿼터·검색 결과 확인. 직선 경로를 정상 주행 경로로 대신 표시하지 않음 |
| 사진 미표시 | photos 행의 실제 파일 경로와 PHOTO_ROOT, 파일 존재/권한, 로그 확인. DB만 복원했는지 확인 |
| 앱 화면이 이전 버전 | Play 설치 버전, 앱 번들 웹 자산과 서버 배포 차이 확인. 업로드 임시본 확인 전 앱 데이터 삭제 금지 |
| 카페 게시 실패 | 서버 로그, 로그인 세션, 편집기 변경, 게시판 권한과 실제 게시글 존재 여부 확인 후 재시도 |

## 인계 완료 조건

저장소 권한만 전달한 상태는 완료가 아니다. 인수자는 새 PC에서 실행·서명 빌드·테스트 배포를 할 수 있어야 하고, 기존 업로드 키와 DB+사진 백업으로 복구할 수 있어야 한다.
외부 서비스 소유/결제 책임, 장애 대응자, 인계 이후 유지보수 범위를 명시한다. 승인 후 이전 담당자의 불필요한 접근 권한을 회수한다.
